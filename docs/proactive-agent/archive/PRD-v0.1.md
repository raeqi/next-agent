# 拾遗：一个不用吩咐的个人 Agent（产品高阶文档）

> 2026-11-11 方向更新：拾遗是通用桌面观察助手。新应用进入前台时询问是否观察，允许/不看分别持久保存；已允许应用的页面文字变化进入通用机会判断，聊天承诺识别作为增强能力保留。观察不等于操作授权：建议卡可请求准备结果，用户另行确认后可粘贴到来源应用，不自动发送。
>
> 当前实现边界：仅观察前台窗口，通过本机 OCR 比较文字变化；首次画面建立基线，变化后限频调用模型。系统及敏感应用跳过。当前操作为确认后的粘贴，依赖 macOS 辅助功能权限；尚未实现通用点击规划、辅助功能树读取、重复动作接管、自动操作策略和执行结果验证。下文旧微信 M2 描述保留为阶段记录。


> 暂名「拾遗」：替你捡起随口答应、却差点掉在地上的事。
> 版本 v0.1 · 2026-11-07 · 面向：Kimi Agent 应用团队命题的原型方案
> 配套：[框架设计](./ARCHITECTURE.md)

---

## 1. 一句话

**Personal agent 的下一步不是更能干，而是不用你吩咐。**
拾遗常驻在你的桌面角落。它看得见你在各个窗口里做的事，会自己发现「这件事我可以接手」，带着做好的草稿来找你。你只需要点「接受」或「不要」，它也会从每一次「不要」里学会你的做事方式。

---

## 2. 为什么是现在（判断）

| 阶段 | 形态 | 用户关系 |
|---|---|---|
| ① Chat | 你问它答 | 用完就关 |
| ② Cowork / Agent mode | 交给它一个任务，它跑完交付 | 一次性委托 |
| ③ Personal Agent | 常驻、有记忆、有自己的电脑、会主动找你 | 一个持续存在的「它」 |

到 2026 年底，③ 已经从风口变成了标配：开源的常驻 agent 爆火，各大厂跟进做托管版，Kimi 也已经有了 Claw。
**标配之后的落差是：有了常驻 agent，却不知道让它干什么。** 常驻 agent 的价值上限，卡在用户能想到多少任务上。

所以真正的瓶颈已经从「agent 能不能干」转移到了**人的带宽**：

- 人想不到可以委托什么（发现）
- 人没空一直盯着（监督）
- 人不敢放手（信任）
- 人每次都要重新交代一遍（积累）

拾遗回应的就是这四点。另外，它满足模型厂最在意的一条：**模型越强，这个设计越值钱**。模型越能干，「替你想到该干什么」就越是剩下的瓶颈。

---

## 3. 目标用户

**高信息密度的职场人**：每天在聊天、文档、邮件、日程之间来回切换，随口答应的事多，最怕漏。
原型主角（暂定）：**一家创业公司的产品经理 林夏**。她一天里会给老板、同事和外部合作方答应七八件小事，同时还要写周报、准备评审。

---

## 4. 产品原则

1. **先做好，再开口。** 它不说「要我帮你做 X 吗？」，而是说「X 我已经做好了，要发吗？」。开口时必须带着可以直接交付的东西。
2. **不值得就闭嘴。** 打扰是最大的成本。每一次开口都要先过「这一刻值不值得」这一关，宁可少说。
3. **原件永不被碰。** 改动一律落在影子副本上，以修订模式叠加在原件之上。点「接受」才写回原件，并且随时可以撤回。
4. **主动要可解释。** 每条建议都附上「我为什么找你」：依据来自哪个窗口、哪句话、哪份文件。
5. **驳回就是教它。** 每一次「不要」都可能沉淀成一条你看得见、改得了的规则，写进《我的工作方式》手册。
6. **看与不看由你决定。** 它有一双「眼睛」，你可以随时关掉；遇到私密窗口时它自动闭眼，这部分内容不出本机。

## 5. 核心体验（四个场景 + 一个仪式）

| # | 场景 | 它看到了什么 | 它做了什么 | 你需要做什么 |
|---|---|---|---|---|
| 1 | **承诺追踪**（杀手场景） | 你在群里说「明天上午发你竞品对比」 | 记下这个承诺；第二天早上之前，基于会议纪要和数据表起草好竞品对比文档 | 早上看一眼，点「发送」或者改两句 |
| 2 | **跨上下文纠错** | 你在周报里写「DAU 12 万」 | 发现上周报表里是 10.8 万，以修订的形式标出来，附上出处 | 接受或忽略这条修订 |
| 3 | **状态变化的连锁处理** | 航班延误两小时（外部事件） | 重排后续安排：起草会议推迟的通知、修改接机时间 | 不在电脑前时用语音（耳机）拍板 |
| 4 | **重复动作接管** | 你第三次把表 A 的数据手动复制到表 B | 提议「以后这件事交给我」，确认后变成一个常驻任务 | 点一次「交给你」 |
| ★ | **下班收尾** | 一整天下来的承诺台账 | 「今天你答应了 3 件事，2 件已经起草好，1 件需要你」 | 花 1 分钟清空 |

贯穿四个场景的一条暗线是 **「越用越像你」**：在场景 1 里你驳回一处「我觉得……」的写法，并告诉它「给老板的东西别用『我觉得』」。手册里随即多出一条规则；到了下班收尾时，它新起草的东西已经自动遵守这条规则。

## 6. 真跑哪一条链路：PPT、Word，还是别的？

**结论：不选 PPT。载体用「文档 + 修订模式」，但核心案例不是「改一份文档」，而是「承诺 → 交付」这条链路。**

| 候选 | 优点 | 问题 |
|---|---|---|
| PPT | 视觉冲击强 | ① 版式质量依赖视觉能力，文本模型做 PPT 容易显得粗糙；② 幻灯片很难做「修订叠加」；③ 「帮我改 PPT」本质上是 cowork 的任务式委托，体现不了「不用你吩咐」 |
| Word | 修订模式是现成的心智，正好对上「原件永不被碰」；DS 模型擅长文本 | 只是改一份文档的话，同样落回任务式委托，主动性不够 |
| **承诺 → 交付（推荐）** | 一条链路同时证明三件事：**主动发现**（从聊天里抓到承诺）、**跨上下文**（把会议纪要、数据表、往来邮件串起来）、**越用越像你**（驳回 → 手册 → 下一份自动遵守）。交付物是一份文档，用修订模式呈现 | 需要设计好「看起来真实」的素材，包括聊天、纪要和数据表 |

这条链路全程是文本，DS 模型能真跑、跑得稳，评审也能一眼看懂哪段是真的。PPT 窗口可以留在假桌面里当背景，不作为主线。

## 7. 演示动线（评审 5 分钟）

「林夏的一天」，按时间推进，一幕一幕点：

1. **前一晚 17:47 随口一句**：林夏在群里说「明天上午发你竞品对比」。桌宠只点了下头，不出声；「它看到了什么」里能看到同一时段的停机通知、团建接龙都被判为「忽略」。→ *不打扰*
2. **09:00 早安**：桌宠探出头：「你昨晚答应王总的竞品对比，我已经起草好了。」打开后是影子副本，每个编号都能点开看原文。→ *主动*
3. **09:05 划掉一句**：林夏删掉一句「我觉得……」，并说明原因。桌宠提议记住这条规则，她点头后，手册里实时多出一条。→ *学习*
4. **10:30 写周报**：她敲下「DAU 12 万」，原文上浮出一条修订：「数据表里是 10.8 万」。接受后可以撤回。→ *跨上下文*
5. **14:00 打开网银**：桌宠闭眼，菜单栏显示「私密窗口 · 拾遗没在看」。在这之前的 11:22，她随口答应陈默「下午给你意见」，被记了下来。→ *信任*
6. **16:00 航班延误**：林夏离开电脑，耳机里问「张总的饭改约、接机改时间都备好了，要发吗？」她说「发」。→ *离开电脑也能拍板*
7. **18:30 下班收尾**：「今天你答应了 3 件事」，两件已经划掉；给陈默的草稿已备好，标注「已按手册第 1 条写」。→ *越用越像你*

**啊哈时刻**：第 7 幕里，评审亲眼看到第 3 幕教的那条规则生效了。

## 8. 信任与隐私

- **动作分级**：只读 < 起草（影子副本） < 修改原件 < 对外发送 < 涉及钱。默认只放开前两级，后几级一律要拍板。
- **信任梯度**：同类动作被连续接受后，可以从「先问」升级到「先做、事后告诉你」，例如修正错别字。升降级都会记录在案。
- **感知边界**：桌宠的眼睛开关；私密窗口名单；敏感内容在本机就过滤掉，不送上云。
- **可追溯**：每一次开口、改动和发送都有审计记录，可以回看依据。

## 9. 衡量指标

| 指标 | 含义 | 期望方向 |
|---|---|---|
| 主动建议接受率 | 开口的价值 | ↑ |
| 打扰率（被忽略或关掉的开口次数 ÷ 总开口次数） | Clippy 风险 | ↓ |
| 承诺兑现率 | 核心场景是否成立 | ↑ |
| 同类驳回率随时间变化 | 是否越用越像你 | ↓ |
| 每日拍板总时长 | 人的带宽占用 | ↓ |

## 10. 对模型厂的价值与商业判断（简）

- **入口**：常驻 agent 是模型厂的个人入口，比单次任务的 cowork 黏性更高。
- **数据飞轮**：每一次接受或驳回，都是真实工作场景里的偏好数据。
- **模型越强越值钱**：长程能力和多 agent 能力越强，「替你想到该干什么」就越成为差异化所在。
- **风险**：最大的是平台风险，屏幕感知的天然拥有者是操作系统；其次是读屏成本，必须分层筛选；还有企业合规和打扰问题。应对思路见[框架设计](./ARCHITECTURE.md)里的筛选层和信任层。
